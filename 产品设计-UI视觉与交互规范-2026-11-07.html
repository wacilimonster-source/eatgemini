01设计原则

控制台是「低频查看、出事才来」的工具页。设计目标不是让用户爱看，而是来的时候 10 秒内看懂、走的时候放心。

原则含义在界面上的落点
1 · 状态即设计这个产品的核心是「额度状态机」，界面首要任务是让状态机可见呼吸状态灯 / 三段用量仪表 / 状态色只许表状态不许装饰
2 · 诚实优先不知道就说「—」，不估算、不编造恢复时间未知值统一 —；「本地估算」永远带角标记；确认型文案给预期
3 · 三次点击到底任何失败/降级，3 次点击内得到「为什么、影响了谁、何时恢复」搜索直达详情抽屉、统计卡可点击跳转筛选、展开行就地解释
4 · 安静的精密像仪表盘不像游乐场：低饱和底 + 高信号色，动效只用于表达状态变化中性灰蓝底座；语义色仅 5 种；动效仅 120/200/320ms 三档
5 · 不吓唬新手目标用户不熟命令行；危险操作要拦，专业参数要藏破坏性操作二次确认；policy 全部收进「高级」折叠区；每个字段配一句人话

02色彩系统

深色为默认主题（桌面常驻工具 + 用户群体偏好），浅色跟随系统。两套主题共用同一组语义令牌，组件代码零改动。

2.1 中性色阶（深色）

底座是偏蓝的深灰（不是纯黑），保证长时间注视舒适；五级表面承担层级，边框承担分隔。

2.2 语义色（唯一允许表达状态的色）

五色封顶。每个语义色配 *-subtle 底色用于 pill / banner / 高亮。装饰禁用语义色，语义色禁作装饰。

2.3 浅色主题映射

浅色不是简单反色：底色改冷纸灰 #F3F5F9，卡片纯白靠 line-1 与轻阴影分层；语义色整体加深保证 4.5:1 对比度（warn 深化为 #96690B，避免浅黄在白底上看不见）。右侧主题按钮可实时预览全部原型。

2.4 图表专用色

04图标体系

一套 48 枚的 inline SVG sprite（本页 HTML 顶部即完整源码），风格为 1.75px 圆头描边、24 网格、currentColor。构建期内嵌于 index.html，引用方式 <svg class="ic"><use href="#i-key"/></svg>——无外链、无字体文件、随主题变色。

4.1 绘制规格

项规格理由
网格 / 视窗24×24 viewBox，图形落在 3–21 安全区缩到 12/14/16/20px 不糊
描边1.75px · round cap · round join · 不填充圆润但不软塌，与 9–14px 圆角体系一致
颜色stroke: currentColor跟随文字色与语义色，深浅主题自动适配
默认尺寸16px（导航/按钮），12–14px（pill/表内），20px（空态）与文字行高对齐，垂直 -3px 校正
禁令禁止多色图标、禁止填充式混用、禁止第三方图标库混入保持唯一视觉语言；等线风格不统一会立刻显糙

05布局与应用外壳

外壳 = 顶栏 + 侧栏 + 内容区三段式。所有页面共用，用「品牌位 + 状态灯 + 网关胶囊 + 倒计时」四件套取代现在松散的顶栏。

区域规格说明
顶栏 topbar高 52px · 左右留白 16px · 元素间距 14px左：品牌（logo 26px + 名 + 版本徽标）→ 分隔线 → 状态芯片；中：网关胶囊；右：刷新、倒计时
侧栏 sidebar宽 200px · 内边距 12px/10px · 项高 36px 圆角 9px上：7 个导航项（图标+文字）；底部固定：退出（danger-ghost）+ 版本信息脚注

7.3 关键交互细节

  • 复制反馈：点击复制 → 图标 120ms 换成 i-check（主色）→ 1.2s 换回 → toast「已复制 xx」。所有复制动作统一（网关地址 / 连接码 / 请求 ID / 令牌）。
  • 实时数据：SSE 推送不直接改表格——先累计到插入条（"有 N 条新请求"），用户点击插入；插入行闪烁 1.6s。统计卡数字直接更新并闪一次。
  • 展开行：点击整行任意处展开（不只箭头）；同时只允许一个展开行（展开新行收起旧行），避免长页面失控。
  • 抽屉：Esc / 点遮罩 / 关闭按钮三种方式；打开时焦点移入抽屉，关闭后归还触发按钮。
  • 弹窗：确认词类弹窗禁用点击遮罩关闭（防误触丢上下文）；普通弹窗可。
  • 导航切换：内容区淡入 120ms；保留各页滚动位置；切换不重新请求快照（30s 轮询 + SSE 共用）。
  • 键盘：Tab 顺序 = 侧栏 → 顶栏 → 内容；表格行可 Enter 展开；`/` 聚焦请求搜索框。
  • reduced-motion：系统开启「减弱动态效果」时，动画时长压到 0.01ms（呼吸灯与骨架除外，改为静态）。
  • 表单保存：设置页「保存」始终可见；有未保存修改时按钮变主色 + 出现「未保存」pill；离开分区时提示。

09文案与语气规范

语气关键词：平实、具体、不装懂也不装傻。不说「哎呀出错了」，也不说「RETRY_AFTER_EXCEEDED」。

9.1 术语表（全应用唯一叫法）

统一用词不使用原因
档位profile / 配置集中文产品全中文
降级fallback / 切换 / 回退核心行为，一词贯穿概览/记录/事件
封锁禁用 / 隔离 / banned强调「暂时不可用」，配恢复时间
Token 用量tokens / 字数与「访问令牌」区分：后者一律叫「令牌」或「连接码」
本地估算预测 / 推断暗示非官方口径，页面固定配口径说明
上游Google 服务器 / API 端与「客户端」相对；面向用户解释时可用「Google 侧」

9.2 错误文案模板

四段式：发生了什么 → 影响了谁 → 你可以做什么 →（可选）技术细节折叠。
例：「Google API Key 已失效（09:12 验证失败）→ 客户端请求将被拒绝 → 更新 Key → · 细节：401 API_KEY_INVALID」
禁止：只给状态码；把责任推给用户（「你输入错了」）；模糊归因（「网络异常，请稍后再试」用于一切错误）。

9.3 诚实表达

  • 未知的数值一律「—」，并在旁边用微字说明原因（如「上游未返回」）。
  • 恢复时间未知就写「恢复时间未知」，给出替代信息（「将在下一次探测后更新」）。
  • 「约 N 分钟后重试」必须是引擎真实参数，不允许文案编一个好看的整数。
  • 消耗额度的动作（测试消息）必须在触发前说明「约消耗 1 次当日额度」。
